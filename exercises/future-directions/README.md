# Future Directions exercises

Exercises 1 and 2 ask for written readings of the chapter's records. Exercise 3's
numbers and exercise 4's constructed route arithmetic are regenerated by
`demos/future_directions_demo.py` in `fnd.future-directions.keys-01`.

Exercise 5: diagnose `decision_05.json`. It is a constructed team's decision,
independent of the actual held run. One reversal signal is wrong. The reference
corrected fixture is `future_directions_reference_05.json`.

Exercise 6: repair `watch_06.py`, then run:

```sh
python -m pytest exercises/future-directions/test_exercise_06.py -p no:cacheprovider
```

The untouched starter deliberately fails five checks. For the reference
reference, add `FUTURE_DIRECTIONS_EXERCISE_REFERENCE=1` to the command. The check
takes the persisted state and consecutively numbered requests. A failed month
names the next 2,000 requests, including referrals, as a separate confirmation
cohort. Its check reads only matured paid outcomes. An incomplete or immature
confirmation stays pending. A matured confirmation passes to clear or fails to
reverse. Referred outcomes are inaccessible in the test fixtures.

Budget withdrawal is wired separately by the operational watch. The current
run keeps the incumbent because partner evidence is missing, so there is no
post-adoption month to rerun. Do not interpret the reference fixtures as an
adoption, a grant of authority or a deployment.
